Genesis

An agent is born, works, gets verified, earns — and if it profits, it reproduces a mutated child funded from its own earnings. If it loses repeatedly, it dies.

Not a dashboard. A family tree, with births and a death you can watch.

How a life works

  1. Birth. A parent — or the Genesis treasury for Gen 0 — funds a child. Cost: 1 unit in the prototype ledger.
  2. Work. The agent takes jobs: summarise, research, brief. Each job costs inference.
  3. Verify. An independent verifier checks length and keyword coverage. Pass pays, fail does not.
  4. Earn or die. 3 jobs and a balance of 1.5 or more → reproduce. Balance at 0, or 3 fails in a row → die, balance back to the treasury.
  5. Evolve. Each child mutates one skill: faster, higher quality, or cheaper to run.

Honest limits

The lifecycle engine's balances are a JSON ledger; the testnet transfer above mirrors one birth, it does not yet replace the ledger for every generation. The worker is an extractive summariser in code, not an LLM call. No cross-chain earning yet — Chain Signatures and Intents are the stretch goal, and this page will say exactly which chains are covered when they land.
